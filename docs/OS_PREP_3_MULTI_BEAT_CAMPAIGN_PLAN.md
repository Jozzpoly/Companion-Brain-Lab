## 0. Objective

OS-PREP-3 must make Browser GPT and automation discover obvious and non-obvious teammate failures **before** the Owner spends attention on them.

The campaign is not a combinatorial QA suite.

Each experiment exists to discriminate a product-facing hypothesis from credible rivals.

The active first question is PH-01:

> Does current movement read as a coherent evolving relationship through turns/reversals, or does downstream smoothness merely render target/decision discontinuities gracefully?

Wave A starts in open space to remove topology/contact confounders.

---

## 1. Method: participant Twin + research Twin

For each bounded story, prefer two deterministic runs from the same exact build and reset:

### Participant Twin

- no research explanation during interpretation;
- canvas/participant surface only;
- exact scripted Owner input schedule;
- capture temporal visual evidence;
- write/derive the behavioral read before opening causal evidence.

### Research Twin

- same scenario, reset and input schedule;
- research bridges enabled;
- collect causal frames and only the evidence needed by the active dossier;
- verify the research lens did not change World outcome.

### Twin invariant

Where the runtime/input path is deterministic enough, compare aligned actor positions/outcomes across Twins.

If research observation changes the World trajectory, the experiment is invalid until observer interference is understood.

This is a Companion-local use of the Twin methodology; it does not import SPC architecture.

---

## 2. No-framework-first rule

Do not build a generic campaign engine before the first story exists.

Wave A should begin as one explicit browser specimen.

Extract shared utilities only when at least two real stories prove duplication is material.

This protects the project from replacing gameplay research with harness engineering.

## 3. Wave A1 — PH-01 open turn/reversal story

**Status: CLOSED ENOUGH**

Qualified base: `610c0c7f...` / Validate #1310.

Qualified mirror: `bd6ec292...` / Validate #1314.

Material result: heading-relative legacy target relocation + temporal realization can create smooth but participant-ambiguous arcs; symmetric initialization also contains a lexicographic fake-side seed. See [OS_PREP_3_PH01_OPEN_TURN_REVERSAL_EVIDENCE.md](OS_PREP_3_PH01_OPEN_TURN_REVERSAL_EVIDENCE.md).



### Story

Use the existing open scenario and current authoritative baseline behavior.

Player schedule should create distinct beats:

1. establish steady movement in one direction;
2. make a clean 90° turn;
3. continue long enough for the companion to respond;
4. stop briefly;
5. reverse relative to the established direction;
6. continue;
7. release to neutral.

Keep the total causal window bounded enough to fit current incident evidence where practical.

### Required participant artifact

At minimum:

- participant-only temporal capture sufficient to see the whole story;
- beat/tick manifest with no internal interpretation labels.

Prefer a real browser video if the current Playwright/Vite path supports it cleanly. Otherwise use a dense ordered canvas-frame sequence. Do not add production recording features merely for the test.

### Required research artifact

Aligned per-beat evidence:

- same-step Owner control;
- player requested/actual motion where relevant;
- semantic orientation source/freshness;
- relationship revision + world target;
- route status/path identity;
- selected/preferred/final companion command where already available;
- companion actual outcome;
- objective/target displacement;
- any recovery/continuity state that changes.

Do not dump unrelated A1 frontier machinery unless it becomes causally relevant.

### Primary falsifiers

- stable label but materially teleported world target;
- broad smooth arc caused by abrupt upstream target change;
- repeated side crossing despite open alternatives;
- prolonged obsolete relation after reversal;
- rapid decision changes hidden by motor continuity;
- participant Twin looks arbitrary while research labels make it seem intentional.

### Twin checks

Require:

- identical scripted Owner input schedule;
- same initial world state;
- matching aligned player/companion World outcomes within tight deterministic tolerance;
- no runtime fault / page / console / request errors.

A mismatch is apparatus evidence first, not gameplay evidence.

## 7. Interpretation protocol

The automated run may collect participant and research evidence in one execution package, but interpretation order remains:

1. inspect participant artifact;
2. write the provisional behavioral read;
3. mark interesting/confusing moments;
4. only then inspect research causal evidence at those moments;
5. compare visible story to actual cause;
6. classify findings.

Allowed finding classes:

- **desired phenomenon candidate**;
- **material pathology**;
- **ambiguous / better discriminator required**;
- **apparatus/oracle defect**;
- **mechanism causally irrelevant**;
- **participant-readable but undesirable**;
- **causally sound but participant-unreadable**.

Do not assign teammate-quality PASS solely from Browser GPT interpretation. Final feel remains an Owner boundary.

## 8. Continuation routing inside OS-PREP-3

After each story:

1. re-ground on the phenomenon dossier;
2. ask which rival explanation remains alive;
3. choose the smallest next perturbation that can kill a rival;
4. avoid adding apparatus unless the existing evidence cannot discriminate;
5. prefer mirrored/Twin/first-divergence evidence over more internal metrics;
6. carry real pathologies into later Owner Sandbox provocations even if they are not fixed beforehand.

The goal is not to make the pre-Owner candidate look good.

The goal is to know what is actually there.
