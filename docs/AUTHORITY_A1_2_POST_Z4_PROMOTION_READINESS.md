### Not yet qualified for live movement authority

**No production decision certificate / winner contract**

`A1CandidateEvidenceCertificate` is deliberately a per-candidate evidence bundle. Its contract explicitly states no selection, no weighting, no transitive order and no runtime authority. The current H1 structured frontier is likewise research-only. There is no production rule saying when a frontier state is sufficient to submit one command.

**No authoritative DIRECT execution contract from A1 proposal identity**

A1.2o names `commandVelocity` as executable DIRECT command identity, and same-physics rehearsals consume it as raw world-unit velocity. But live World authority still consumes `MotionIntent`, and `A1AuthorityRuntime.resolveCompanionIntent()` always returns the baseline intent. The exact boundary `A1 proposal -> submitted MotionIntent -> A0 command evidence` has not been qualified for an A1-owned action.

**No A1 prediction-to-outcome closure**

A0 can attribute an executed companion command after a World step, and A1 can rehearse predicted trajectories. Those two evidence surfaces have not yet been joined for an A1 proposal so that one record can prove:

- which proposal was submitted;
- what first-step / bounded future it predicted;
- what command A0 says actually entered the World;
- what the companion and player bodies actually did;
- whether contact/downstream constraints changed the result;
- prediction error and causal disposition.

Without that closure, turning on A1 movement would create action before the project can honestly explain the consequence of that action.

**TEMPORAL remains a label, not a realized actuation contract**

The current A1 runtime exposes `direct` and `temporal` experimental variants, but both remain pass-through. No TEMPORAL realization semantics are qualified. This does not block a future DIRECT-only bounded activation, but it forbids treating TEMPORAL as already implemented.

**Embodied selected-behaviour feel remains unproven**

Z4b proves bounded manual tangent-class physical specimens can execute safely. Z4f/g prove current shadow evidence can represent and explain tangent support. Neither proves that a sequence of decisions produced from the eventual promotion contract is readable, stable or useful as teammate behavior.

## 5. Next bounded target — P0 DIRECT execution/outcome closure

P0 should remain **zero live A1 authority**. It is an isolated promotion-rehearsal contract, not a selector.

Given one caller-supplied, already-qualified concrete DIRECT proposal from an exact A1 decision state, P0 should prove that the project can carry that exact proposal through the real execution representation and close the resulting evidence loop without granting the research system permission to choose the proposal.

Required chain:

`A1ConcreteCommandProposal.commandVelocity`
→ research-only DIRECT execution capsule
→ exact `MotionIntent` representation under current companion capability
→ isolated twin World real `step()`
→ A0 `companionVelocityCommand` + `companionOutcomeAttribution`
→ comparison with the same-physics rehearsal's corresponding first-step prediction.

Required invariants:

1. caller supplies the proposal; P0 never ranks or selects;
2. proposal/source tick/capability identity must align exactly;
3. conversion to `MotionIntent` must not change command velocity within explicit numerical tolerance;
4. actual A0 command evidence must recover the same proposal velocity;
5. query rehearsal must not mutate the source World;
6. isolated real execution must not mutate the control/source World;
7. predicted and isolated-real first-step actor states should match within a tight evidence-bound tolerance when both receive the same H1 player velocity and companion command;
8. A0 attribution must remain explicit rather than being reinterpreted by P0;
9. no A1 runtime variant may gain authority as part of P0;
10. failure must identify whether the divergence occurred at representation, World execution, A0 command provenance or physical prediction.

Initial fixtures should include at least:

- authored head-on tick 0, where H1 tangent support is known;
- a later head-on state around the tick-8 transition, because it carries nonzero companion velocity and exercises `MAINTAIN_CURRENT`/tangent command identity under a live moving state;
- one non-head-on/open control if required to falsify accidental fixture coupling.

P0 succeeds only if it gives us a trustworthy actuator/outcome boundary. It does **not** make a proposal authoritative.
